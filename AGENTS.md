# ansible-el-compat — Agent Guide

## Project overview

This is an Ansible collection (`carlijoy.compat`) distributed as a Python package
(`ansible-el-compat` on PyPI).  It provides drop-in replacements for
`ansible.builtin.*` modules that fail on Enterprise Linux 8 when used with
`ansible-core >= 2.17` (which requires Python 3.10+ on managed hosts, but
`python3-dnf` only exists for Python 3.6/3.9 on EL8).

**Core mechanism:** The distributed module is a self-executing zip bundle
containing the original `ansible.builtin.dnf` from ansible-core 2.15 and all
its `ansible.module_utils.*` dependencies.  The bundle carries a
`#!/usr/libexec/platform-python` shebang so Ansible treats it as a binary module,
copies and runs it directly without the ansiballz wrapper, under the EL8 system
Python that has `python3-dnf` available.

**Binary module argument protocol:** Because Ansible classifies the file as
binary (the zip magic bytes `PK\x03\x04` are non-text), it writes the module
arguments as bare JSON to a temporary file and passes its path as `sys.argv[1]`
— no `ANSIBLE_MODULE_ARGS` wrapper, no stdin, no `WANT_JSON`.  The
`build-script/main-template.py` bootstrap (embedded as `__main__.py` in the
zip) reads that file, strips `_ansible_*` keys not accepted by ansible-core
2.15, wraps the result in `{"ANSIBLE_MODULE_ARGS": ...}`, and injects it via
`ansible.module_utils.basic._ANSIBLE_ARGS` before calling the bundled
`dnf.main()`.  This bypasses the controller-version mismatch for newer internal
keys (e.g. `_ansible_ignore_unknown_opts`) added after ansible-core 2.15.

The bundle is built by `build-script/build_dnf_bundle.py`, automatically
invoked by the hatch build hook during `uv build`.  The resulting file
`src/ansible_collections/carlijoy/compat/plugins/modules/dnf` (no `.py`
extension — that signals a binary module to Ansible) is generated at build
time and is **not** committed to git.

## Development setup

```bash
# Clone and enter
git clone https://github.com/CarliJoy/ansible-el-compat
cd ansible-el-compat

# Install all dev dependencies (creates .venv automatically)
uv sync --group dev

# Install git hooks
uv run prek install
```

## Running checks

```bash
uv run prek run --all-files  # lint (ruff) + type check (mypy) + misc hooks
```

**Run this after every set of changes before reporting work as done.**  It is
fast and catches lint, formatting, and type errors in one shot.

## Running tests

Tests are integration tests — they require Docker to be running.

```bash
# All integration tests (~3 min first run due to image pull)
uv run pytest tests/ -v

# Skip integration tests (fast, no Docker needed)
uv run pytest tests/ -v -m "not integration"
```

The integration suite spins up `almalinux:8` via testcontainers, bootstraps it
with `openssh-server + python3.12 + epel-release`, and runs real
`ansible-playbook` commands against it via subprocess.  This validates the EL8 +
Python 3.12 combination that is broken with `ansible.builtin.dnf`.

## Rebuilding the bundle

The binary module `plugins/modules/dnf` is generated at build time by the
hatch hook and is not committed to git.  Run the script manually only to
inspect the output or to test changes to the build script itself.

```bash
uv run build-script/build_dnf_bundle.py
```

The script uses inline `uv` script metadata to pin ansible-core 2.15 in an
isolated environment. It then:
1. Locates `ansible/modules/dnf.py` in that environment
2. Recursively collects all `ansible.module_utils.*` imports via AST
3. Packs everything into a zip with a `__main__.py` bootstrap
4. Prepends `#!/usr/libexec/platform-python` and writes the executable to
   `src/…/plugins/modules/dnf`

## Versioning

Version is derived from git tags via `hatch-vcs`.  Never edit `_version.py`
manually — it is regenerated on every build.

```bash
# Tag a release (triggers the release workflow)
git tag v1.0.0
git push origin v1.0.0
```

## Adding a new module

1. Identify the upstream `ansible.builtin.<name>` source and its Python library
   dependency that is unavailable on EL8 under Python 3.10+
2. If the same bundle approach applies, extend `build_dnf_bundle.py` or create
   an analogous script for the new module
3. Add integration tests in `tests/test_<name>.py`
4. Update `README.md` with the new module's options table

## Release process

1. Ensure `main` is clean and CI is green
2. The bundle is auto-generated by the hatch hook during `uv build` — no manual rebuild needed
3. Tag: `git tag v<semver> && git push origin v<semver>`
4. The `release.yml` workflow:
   - Builds wheel + sdist
   - Publishes to PyPI via OIDC trusted publishing (no token needed)
   - Builds the Galaxy `.tar.gz` and publishes via `ANSIBLE_GALAXY_API_KEY` secret
5. Create a GitHub Release from the tag (optional, but nice for changelogs)

## Key design decisions

- **Bundle the original module, don't reimplement** — ships the actual
  `ansible.builtin.dnf` from ansible-core 2.15 with its full module_utils
  dependency tree; no feature gaps, no behavioural differences
- **Binary module via shebang** — by omitting the `.py` extension and adding
  `#!/usr/libexec/platform-python`, Ansible copies and executes the file
  directly without ansiballz wrapping, so it runs under the system Python that
  has `python3-dnf`
- **`/usr/libexec/platform-python` is stable on EL8** — it is the RHEL/CentOS
  system Python, always present and always has `python3-dnf` available
- **pip-installable collection** — placed under `src/ansible_collections/` so
  `pip install ansible-el-compat` puts the collection exactly where Ansible
  auto-discovers it (`site-packages/ansible_collections/`)
- **GPL-3.0-or-later** — the bundle contains ansible-core source (GPL-3.0-or-later);
  the collection therefore ships under the same license
- **hatch-vcs** — single source of truth for version; derived from git tags

## Constraints

- Python 3.10+ required on the **controller** (ansible-core >= 2.17 requirement)
- Python 3.12 is the fixed development/CI version (`.python-version`)
- Target hosts must have `/usr/libexec/platform-python` (always present on EL8)
  and `python3-dnf` installed (default on EL8)
- Tested target OS: AlmaLinux 8 (also works on Rocky 8, RHEL 8)
